# Jurnal PKL — DineFlow POS

## Kamis, 20 Agustus 2026 — Manajemen Password (Ganti Mandiri & Reset oleh Admin) + Riset Deployment

Pada sesi ini, kegiatan praktik kerja lapangan difokuskan pada dua hal, yaitu penambahan fitur manajemen kata sandi pengguna dan riset strategi deployment untuk mempersiapkan presentasi progress serta hosting online. Sebelumnya sistem baru memiliki kata sandi bawaan 1234 yang tidak dapat diganti, sehingga ditambahkan fitur ganti kata sandi mandiri pada antarmuka pengguna, yaitu modal `ChangePasswordModal` yang dipasang pada bilah navigasi atas sehingga seluruh peran (admin, kasir, pelayan, dan dapur) dapat mengganti kata sandi sendiri dengan memvalidasi kata sandi saat ini, kata sandi baru minimal enam karakter, dan konfirmasi yang sama, yang memanfaatkan titik akhir `POST /change-password` yang sudah tersedia pada pengendali autentikasi backend. Selanjutnya ditambahkan fitur reset kata sandi oleh admin pada manajemen staf, yaitu titik akhir baru `POST /users/{user}/reset-password` yang khusus untuk peran admin dan mengembalikan kata sandi staf menjadi 1234, lengkap dengan tombol reset beserta konfirmasi pada tabel staf. Pengujian otomatis backend ditambah dua kasus, yaitu admin dapat mereset kata sandi staf dan pengguna non-admin ditolak dengan kode 403, sehingga total pengujian backend menjadi lima dan seluruhnya lulus; pengujian frontend tetap delapan belas dan seluruhnya lulus beserta build dan lint. Seluruh perubahan tersebut kemudian di-commit dan di-push ke repositori pada komit `8597496`.

Selanjutnya dilakukan riset deployment, karena hosting yang tersedia gratis umumnya mewajibkan kartu kredit yang belum dimiliki. Disimpulkan bahwa DineFlow memerlukan server dengan kontrol penuh karena memakai Reverb (WebSocket) dan Redis untuk fitur real-time, sehingga pilihan yang valid adalah server sekolah (tanpa biaya, prioritas pertama untuk ditanyakan kepada pembimbing), VPS IDCloudHost 2 Core 2 GB seharga Rp87.000 per bulan dengan pembayaran e-wallet tanpa kartu kredit (jalur produksi utama), atau Railway sebagai uji coba 30 hari. Sementara itu, beberapa opsi lain dinilai tidak dapat dipakai, yaitu shared hosting seperti diskon.com dan InfinityFree karena tidak mengizinkan proses WebSocket dan instalasi Redis, serta Oracle Always Free, Render, dan AWS karena mewajibkan kartu kredit (Oracle dapat diakses tanpa kartu melalui Oracle Academy). Hasil riset ini ditulis ke dalam `docs/deployment.md` yang disusun ulang menjadi panduan berjenjang, diperbarui pula `docs/catatan-presentasi.md` dengan harga VPS terkini dan pertanyaan tambahan mengenai server sekolah serta Oracle Academy, dan rencana selanjutnya adalah presentasi progress dengan demo lokal serta penulisan laporan.


## Senin, 17 Agustus 2026 — Uji Manual Menyeluruh, Real-time Menu & Panel Kasir

Pada sesi ini, kegiatan praktik kerja lapangan difokuskan pada pelaksanaan uji manual menyeluruh sesuai panduan pada `docs/uji manual.md`, penambahan fitur real-time ketersediaan menu, serta perluasannya agar seluruh perubahan menu diperbarui secara real-time di semua kanal. Kegiatan diawali dengan menyalakan seluruh layanan pendukung, yaitu MySQL, Redis, backend Laravel, server Reverb, dan frontend Vite, kemudian dilanjutkan pengujian bertahap terhadap tujuh bagian uji manual yang mencakup login dan peran, alur kasir termasuk pembayaran tunai dan QRIS, alur pelayan, tampilan dapur (Kitchen Display) dengan pembaruan status secara real-time, pesan mandiri melalui menu QR, manajemen admin beserta unggah foto menu, serta uji negatif dan keamanan. Seluruh kasus uji berhasil dilalui. Selama pengujian ditemukan dua bug pada pembayaran QRIS, yaitu galat "undefined array key cashReceived" karena pengecekan nilai tunai yang diterima pada pembayaran QRIS yang tidak mengirimkan nilai tersebut, diperbaiki dengan inisialisasi nilai sebagai null apabila tidak ada, serta halaman kosong setelah menandai lunas karena nilai kembalian null yang diproses oleh pemformat rupiah, diperbaiki dengan penanganan nilai null pada halaman kasir dan modal struk. Untuk bagian real-time, sempat ditemukan tampilan dapur yang tidak memperbarui tanpa penyegaran halaman; isolasi dengan listener WebSocket mentah membuktikan rantai pengiriman event dari Laravel ke Reverb hingga ke klien berjalan normal, sehingga masalah dipastikan hanya pada tab browser yang memakai kode lama, dan setelah penyegaran ulang pembaruan real-time terbukti bekerja dalam waktu kurang dari dua detik. Selanjutnya ditambahkan event `MenuChanged` pada kanal publik menu yang disebarkan saat menu dibuat, diperbarui (nama, harga, deskripsi, kategori, status habis, dan foto), maupun dihapus, sehingga katalog pesan mandiri pelanggan yang sudah terbuka dan daftar menu pada panel kasir langsung diperbarui tanpa penyegaran halaman sesuai pernyataan pada dokumen kebutuhan bahwa menu yang habis otomatis tidak muncul lagi. Tahap verifikasi menunjukkan build, lint, delapan belas tes otomatis pada frontend, dan tiga tes pada backend seluruhnya lulus, broadcast event menu diterima oleh listener WebSocket, kemudian basis data di-reset kembali ke data demo melalui `migrate:fresh --seed`, dan selanjutnya tinggal pembaruan dokumentasi serta proses commit ke repositori.

## Sabtu, 15 Agustus 2026 — Finalisasi Race Condition & Perapian Dokumentasi (Fase B5)

Pada sesi ini, kegiatan praktik kerja lapangan difokuskan pada penyelesaian fase B5 mengenai race condition serta perapian dokumentasi. Selanjutnya dilakukan perapian dokumen, yaitu sinkronisasi ringkasan status pada daftar tugas yang menandai seluruh fase A, fase B, dan unggahan repositori sebagai selesai, serta pembaruan panduan uji manual agar sesuai dengan implementasi terkini, seperti pembaruan status pesanan secara real-time menggunakan Reverb tanpa penyegaran halaman, unggah foto menu sebagai berkas, halaman pesan mandiri yang dapat diakses publik tanpa login, dan penyimpanan data pada basis data MySQL. Seluruh pengujian backend lulus dan dokumentasi telah disesuaikan, sehingga tinggal pembaruan log progres serta proses commit ke repositori.

## Sabtu, 15 Agustus 2026 — Implementasi Foto Menu Upload (Fase B4)

Pada sesi ini, kegiatan praktik kerja lapangan difokuskan pada implementasi fitur unggah foto menu menggantikan input URL gambar pada fase B4. Kegiatan diawali dengan menyalakan seluruh layanan pendukung, yaitu MySQL, Redis, backend Laravel, server Reverb, dan frontend Vite, kemudian dilakukan pengembangan pada sisi backend dengan memodifikasi pengendali menu agar menerima berkas gambar dalam format PNG, JPG, atau WebP berukuran maksimal dua megabita, menyimpannya ke penyimpanan publik pada direktori `menu-items`, serta menghasilkan tautan URL absolut yang kemudian disimpan ke kolom gambar menu, sementara dukungan input URL string lama tetap dipertahankan untuk kompatibilitas. Pembuatan tautan simbolis penyimpanan publik melalui perintah `storage:link` juga dilakukan agar berkas dapat diakses secara langsung. Pada sisi frontend, formulir manajemen menu diubah dari kolom input URL menjadi kolom unggah berkas dengan pratinjau gambar, dan layanan HTTP diadaptasi untuk mengirim data dalam format multipart. Selama pengujian ditemukan bahwa PHP hanya mengisi data multipart pada metode POST sehingga permintaan PUT dengan berkas gambar tidak tersimpan, dan perbaikan dilakukan dengan menggunakan teknik method spoofing, yaitu mengirim multipart melalui POST dengan field `_method` bernilai PUT yang dikenali Laravel. Tahap verifikasi menunjukkan pengunggahan berkas gambar berhasil menyimpan URL dan berkas dapat diakses dari penyimpanan publik dengan status sukses, seluruh proses build dan lint berhasil, delapan belas tes otomatis pada frontend dan dua tes pada backend lulus, kemudian basis data di-reset kembali ke data demo melalui `migrate:fresh --seed`, dan selanjutnya tinggal pembaruan dokumentasi serta proses commit ke repositori.

## Sabtu, 15 Agustus 2026 — Akses Publik Menu Mandiri & Logout Revoke Token (Fase B3)

Pada sesi kedua hari ini, kegiatan praktik kerja lapangan difokuskan pada penyelesaian dua masalah yang tersisa pada fase autentikasi (B3), yaitu akses publik pada halaman Menu Pesan Mandiri dan pencabutan token pada saat logout. Kegiatan diawali dengan menyalakan seluruh layanan pendukung, yaitu MySQL, Redis, backend Laravel, server Reverb, dan frontend Vite, kemudian memeriksa bahwa seluruh layanan berjalan normal. Permasalahan pertama adalah halaman katalog pesan mandiri yang membutuhkan login karena rute pengambilan kategori, menu, meja, dan pembuatan pesanan masih berada di dalam grup autentikasi Sanctum, sehingga pelanggan yang tidak login mendapat respons 401. Perbaikan dilakukan dengan memindahkan rute `GET /categories`, `GET /menu-items`, `GET /tables`, dan `POST /orders` keluar dari grup `auth:sanctum` pada file `routes/api.php` sesuai keputusan bahwa kategori, menu, meja, dan pesanan self-order bersifat publik, sementara rute lainnya tetap dilindungi. Permasalahan kedua adalah logout yang hanya menghapus token dari penyimpanan lokal tanpa mencabut token di server, sehingga token yang sudah tidak terpakai masih dianggap valid. Perbaikan dilakukan dengan menambahkan metode `logout` pada kontrak layanan API yang mengirim permintaan `POST /logout` ke server dan membersihkan token lokal, lengkap dengan implementasi pada `httpApi.ts`, stub pada `mockApi.ts`, serta pemanggilan best-effort dari konteks autentikasi. Tahap verifikasi menunjukkan bahwa pengujian menggunakan curl tanpa token berhasil mengakses kategori, menu, meja, dan membuat pesanan self-order dengan status sukses, sedangkan pengambilan daftar pesanan tetap ditolak tanpa token; pengujian login lalu logout membuktikan token lama sudah tidak dapat digunakan setelah logout. Seluruh build, lint, delapan belas tes otomatis pada frontend, dan dua tes pada backend lulus, kemudian basis data di-reset kembali ke data demo melalui `migrate:fresh --seed`, dan selanjutnya tinggal pembaruan dokumentasi serta proses commit ke repositori.

## Sabtu, 15 Agustus 2026 — Penyelesaian Bug Real-time & Finalisasi Fase B2

Pada hari ini, kegiatan praktik kerja lapangan difokuskan pada penyelesaian masalah fitur real-time pada aplikasi DineFlow POS yang pada sesi sebelumnya masih membutuhkan penyegaran manual pada tampilan dapur (Kitchen Display) ketika pesanan dikonfirmasi dari kasir. Kegiatan diawali dengan menyalakan seluruh layanan pendukung, yaitu MySQL, Redis, backend Laravel, server Reverb, dan frontend Vite, kemudian dilakukan proses isolasi masalah secara berlapis menggunakan listener Node.js, penelusuran log server Reverb yang dijalankan dengan opsi debug, serta pengujian WebSocket secara langsung. Hasil isolasi menunjukkan bahwa rantai komunikasi dari Laravel menuju Reverb dan dari Reverb menuju klien WebSocket sebenarnya berjalan normal, namun klien `laravel-echo` versi 2.4 tidak menerima event karena memiliki nilai bawaan `namespace: "App.Events"` yang menyebabkan nama event dibinding menjadi `App.Events\OrderStatusChanged`, tidak sesuai dengan nama event `OrderStatusChanged` yang dikirim server melalui `broadcastAs`. Perbaikan dilakukan dengan menambahkan opsi `namespace: ''` pada file `echo.ts`, sehingga uji coba pada dua browser berhasil menunjukkan pesanan yang dikonfirmasi dari kasir langsung tampil pada tampilan dapur tanpa perlu menyegarkan halaman. Setelah itu, dilakukan verifikasi menyeluruh berupa build, lint, dan delapan belas tes otomatis pada frontend serta dua tes pada backend yang seluruhnya lulus, diikuti reset basis data hasil pengujian kembali ke data demo awal melalui perintah `migrate:fresh --seed` agar data (empat pengguna, sembilan belas menu, delapan meja, dan tiga pesanan) siap digunakan untuk presentasi. Dengan selesainya perbaikan ini, seluruh pencapaian fase B2 telah terpenuhi termasuk NFR pembaruan status secara real-time di bawah dua detik, dan selanjutnya tinggal melakukan pembaruan dokumentasi serta proses commit ke repositori.

## Jumat, 14 Agustus 2026 — Implementasi Real-time (Laravel Reverb + Redis)

Pada hari ini, kegiatan praktik kerja lapangan difokuskan pada implementasi fitur real-time pada aplikasi DineFlow POS dengan menggunakan Laravel Reverb dan Redis sebagai bagian dari fase B2. Kegiatan diawali dengan verifikasi seluruh layanan pendukung, yaitu MySQL, Redis, backend Laravel, server Reverb, dan frontend Vite yang seluruhnya berjalan normal. Selanjutnya dilakukan pengembangan backend berupa pembuatan event `OrderStatusChanged` yang menyebarkan notifikasi perubahan status pesanan secara otomatis ke seluruh kanal (kasir, dapur, pelayan, dan pelanggan) pada saat pesanan dibuat, dikonfirmasi, status item diubah, dan transaksi pembayaran diselesaikan, disertai perbaikan konfigurasi `broadcastAs` serta penataan ulang `OrderController` dan `PaymentController` agar proses broadcast berjalan dengan benar. Pada sisi frontend, dilakukan pemasangan paket `laravel-echo` dan `pusher-js`, pembuatan file konfigurasi `echo.ts`, serta penggantian mekanisme polling lima detik pada halaman dapur (Kitchen Display), kasir, dan pemantauan pesanan pelanggan menjadi langganan channel real-time melalui WebSocket, termasuk perbaikan masalah tampilan halaman yang kosong dengan menambahkan opsi `cluster` pada konfigurasi klien. Tahap verifikasi menunjukkan seluruh proses build dan lint berhasil, delapan belas tes otomatis pada frontend dan dua tes pada backend lulus, serta uji end-to-end pengiriman event real-time berhasil diterima oleh klien dengan waktu respons di bawah dua detik, sehingga pencapaian NFR pembaruan status secara real-time telah terpenuhi. Beberapa hal masih menjadi catatan untuk sesi berikutnya, antara lain pengujian manual pada dua browser yang masih memerlukan penyegaran halaman pada tampilan dapur, perencanaan reset database hasil pengujian, serta proses commit ke repositori.
